# A5 Agent 预约交接

本文件供后续 Agent 和维护人员接手 A5 预约接口与会话推送。用户的自然语言使用方式另见内部交接包中的 A5 HTML 使用说明；该文件包含现场入口与截图，不放入公开仓库。更新现场信息前先核对当前部署，不要把本文中的通用默认值当作现场实况。

## 目标和当前状态

用户可以先布置任务，再让 Agent 创建 A5 预约，或选择本人已有预约并绑定当前会话。布置任务时就询问分配卡被他人占用或无法核实时的处理，以及到期任务未完成时是否续期和如何处理；用户已经明确的选择不重复询问，并保存到执行计划。普通预约进入 `ready` 后，Agent 核对最新分配编号并登记开始；夜间预约按队列规则进入 `active` 后再启动任务。任务运行在用户指定的已有容器，Agent 按预先授权的设置处理续期、停止和释放。

已实现创建、查询和操作预约的接口；服务端保存到号、开始、到期和结束事件；本地接收器通过持续连接获取事件，并将消息交给当前 Codex 桌面会话。事件流与会话推送已用隔离队列、模拟任务验证，空闲的原 Codex 会话也已用模拟事件成功唤醒。**真实业务任务从预约、启动、续期到释放的全链路尚未完成验证；Claude 和其他运行环境的原会话适配器尚未实现或实测。**

任务的业务启动、进度判断和停止由 Agent 按用户计划负责，预约系统本身不执行提交的业务命令。当前没有通用的“业务进程完成”主动事件：任务提前完成时，能否及时释放取决于 Agent 能否观察到完成状态或后续收到其他事件。不可将登记结束当作业务进程已停止，也不可把推送被接收当作任务已经启动或完成。

## 状态与事件

- 新建预约和 `claim`、`extend`、`finish` 使用唯一操作编号；相同编号的重复请求由服务端事务回执去重。客户端结果不明时用原编号 `retry` 或 `action-retry`，不要构造新操作。
- `agent_queue_events` 记录 `ready`、`active`、`due`、`ended`，按工号关联的账号和共同使用人过滤。`ready`、`active` 由数据库状态变更写入；`due` 按每次开始时间和申请时长去重，预约删除时也会补记到期事件；`ended` 在预约记录删除时产生。不要把事件当作当前状态，处理前重新查询。
- `agent-stream` 使用已登录个人会话接收事件流；服务端检查持久事件并向连接中的接收器推送。接收器保存确认过的游标，重连时可补读。客户端不需要定期唤醒 Agent 查询预约。
- Codex 桌面适配器通过当前桌面应用提供的工具向继承的当前会话发送消息，不得将未授权的其他会话当作目标。事件编号已确认时去重；发送结果不确定时保留待核查状态，不盲目重发。接收确认不代表 Agent 已处理。
- `a5_push.py --codex-desktop --plan <绝对路径> --job <预约编号> --background` 继承当前会话身份，检查预约归属及桌面工具，启动后台接收并返回连接状态。计划应保存在用户私有目录，包含任务启动、识别、停止、输出和完成后处理方式。绑定时已到号或已在使用，应立即查询并按计划处理，不依赖新事件。
- 桌面适配器依赖 Codex 应用提供的本地插件及进程环境；升级或重启后可能需要在原会话重新绑定。电脑、接收程序或网络离线时无法保证及时操作，恢复后必须先检查预约和实际任务。

## 不可省略的业务边界

普通预约仅在服务端允许的超时窗口内申请 10、20 或 30 分钟延长，且可能受夜间截止或插空边界限制；夜间预约不能使用该普通续期接口。用户允许且选择由 Agent 估计时，Agent 根据任务进度选择档位。续期被拒绝或无法继续时按任务布置时确认的方案处理并通知；用户选择停止时，只停止对应任务并尽量保留已有输出，不能停止无关任务或整个容器。

2026-11-14 起，A5 现场启用 `midnight_separation`：普通预约跨午夜截短至 00:00 并结束登记，00:00–09:00 暂停开始普通预约，等待队列保留；夜间预约可提前提交，开始时间为 00:00–09:00 前，按所选时长登记，最迟于当天 09:00 结束登记，固定卡位不再因普通任务优先而顺延。配置中的旧 `normal_priority` 值被该模式覆盖，实际状态以接口为准。结束登记不停止实际进程；夜间接管仍须依赖新鲜采集和既有非预约容器处理，信息不完整时可能暂不能开始。现场两条既有夜间预约按用户要求调整为 11 月 15 日 00:00–09:00，保留卡位。

2026-11-18 修复每日清理被午夜隔离模式整体跳过的问题：北京时间每天 09:00 清理上一普通时段的预约，按原申请时间判断，不因到号顺延、调序或重新分配而变成新任务。A5 和 A3-139/140 清理当天 00:00 前提交的普通预约，A3-101/103 清理当天 02:00 前提交的普通预约；夜间暂停期间及当天稍后新提交的普通预约保留，未来夜间预约不受影响。服务错过 09:00 后恢复时按最近的 09:00 边界补清理，每个边界只执行一次。删除预约记录沿用已有 Agent `ended` 事件，清理登记不直接停止实际进程。部署前核对现存旧任务及正在使用的任务，保留一致性数据库备份，不用备份恢复用户已取消的条目。隔离回归见 `test_queue_daily_reset.py`，覆盖两种夜间起点、延迟重启、重复执行和凌晨新预约保留。

先确认实际业务已停止使用分配卡，再按用户选择结束登记或等待；单次“无进程”采样和结束登记都不等于业务已经安全退出。现场可能启用无工号进程拦截和人员名单管控，实际启动前须核对任务归属与运行环境。当前预约接口按用户要求使用自报工号和姓名，不能把它描述为独立的企业身份认证，也不授予管理权限。

## Agent 预约的小鲁班提示

2026-11-18 核对：小鲁班 `/A5预约` 插件只接入查询、私聊确认后的释放和延后，不支持自然语言创建预约。用户明确不接入该创建功能。平台普通聊天可能自行回复“已记录”，但未路由至插件的消息不会调用预约服务；不能将聊天确认当成预约成功。插件收到不支持的操作时明确私聊告知未提交、未占卡，HTTP 通用回执也标记 `Unsupported command; no reservation created`，不返回预约内容；受查询限流时仍保留该否定回执。实际新建请用网页或已配置的预约 Agent，以真实预约编号和开始日期为准。平台自然语言路由不受本服务控制，发布状态未确认的待办不得直接删除或重复发布。

2026-11-17 已核对两组 A3 均开放 Agent 预约操作：101/103 和 139/140 各为独立双机队列，普通时长上限保持 120 分钟。`GET /a5-queue/api/state` 返回 `agent_reservations_enabled`，A3 客户端 `query` 保留该标志及普通时长、夜间起点，供调用方判断实际能力；旧服务缺少该字段不表示禁用。101/103 的 `night_read_only` 仅约束夜间交接时的容器停止，不是预约接口只读，也不关闭独立的无工号拦截。四机任务须分别在两队列预约，两个预约不保证同时成功或同时开始。连接、操作与共同使用人流程见 [A3 Skill](../skills/a3-reservation/SKILL.md)。

2026-11-17 按用户明确要求，四台 A3 设置 `guard.unknown_npu_processes=true`、`guard.unknown_npu_action="container"`：明确无工号的 NPU 进程经新鲜完整采集、实时 NPU 及 PID/容器实例复核后，停止所属整个 Docker 容器。模糊归属、采集失败和过期数据不触发，保护及白名单保留，宿主机进程不扩大处理。每个容器实例写入独立持久回执；停止超时后只核对实际状态，不重复请求；进程退出后也核对未确认回执。该记录不把容器永久列入拦截名单，重新启动且归属已正确的实例不因此被停。A5 默认 `process` 模式仍只处理对应进程，现场 A5 配置未修改。两组 A3 的 `container_guard.py`、`process_exporter.py` 有各自现场叠加版本，保留 101/103 的扩展账号和两组既有策略，不能用通用文件直接覆盖。

Agent 成功创建预约时，服务在同一事务中记录创建通知；新版接收程序成功连接并绑定已有预约时记录绑定通知。通知发送给预约人，共同使用人绑定时会显示绑定者工号，不包含会话或执行计划。通知通过现有快照和小鲁班发送链路异步处理，可能延迟，超过一小时不再发送；重试和同一接收进程重连会去重。每次重新启动接收并完成绑定会产生新的绑定通知。旧版接收程序需升级后才支持绑定通知。平台接受发送不等于用户设备收到，私聊提示不要求确认，也不改变既有到号、开始或超时提醒。

## 共同使用人与夜间表单

Agent 客户端 `shared list/search/add/remove` 复用现有预约网页接口；只有预约申请人可管理。添加前查询两节点一致名单并核对工号姓名；姓名有歧义先询问，传入 `--name` 可校验。网络结果不明确时先查名单。`query` 返回可见预约的共同使用人。午夜隔离模式的夜间时长提交上限为 9 小时，按所选时长登记，超过 09:00 自动截短，日期选择隐藏没有未来五分钟起点的日期；其他部署的旧夜间模式保留原规则。

## 午夜截短与空闲卡通知

预约开始时间可能包含小数秒，截短时长以整秒保存。午夜隔离排程应将结束时间距离边界不足一秒的截短任务视为到达边界，避免额外缓冲进入夜间预约；登记结束不停止进程。小鲁班未登记进程的本人提示仅涵盖占用他人已分配或使用中预约的卡，不含未预约卡；网页分类沿用原规则。站点差异及部署前备份仍须按现场核对。

## 夜间共享容器接管

同一容器同时运行不同夜间预约卡的进程时，不得为了清理未授权卡而停止含有授权进程的容器。进程身份和卡号明确时，仅将冲突卡保持待接管，不应阻塞该节点的其他预约；进程卡号或归属不明、采集不可用仍需按节点等待核实。已进入使用中的预约对容器的保护在后续轮询中继续有效。A5 现场已应用此修复，独立 A3 环境需比较现场策略后再决定如何移植。

## 提前使用编辑与刷新

预约表格自动刷新期间，若提前使用时长下拉框仍获得焦点且该预约仍可编辑，保留表格 DOM 以免系统关闭原生选项框；卡状态和通知仍更新。预约失去编辑资格、时长改变或账号变化时正常重绘。浏览器回归检查覆盖焦点、跨刷新保留选择、单次保存和预约状态变化，适用于 A5 和 A3 页面变体。

## 到号未开始的顺延

2026-11-17：超过 10 分钟未登记开始，释放本次分配并移到首个被其卡位阻挡的同类型、同紧急等级后续任务之后，不再固定下调一位。通过释放全部同时超时分配、分别保留其卡位的排程对比识别资源依赖；其他使用中或已分配预约不会被撤销。被影响任务原本就在前面或没有后续受益任务时不移动。短任务在新顺位仍能不延误前序预约时可以再次到号。原申请时间、到号次数及取消阈值继续保留；手动下调一位仍是独立操作。
