# A5 Agent 预约交接

本文件供后续 Agent 和维护人员接手 A5 预约接口与会话推送。用户的自然语言使用方式另见内部交接包中的 A5 HTML 使用说明；该文件包含现场入口与截图，不放入公开仓库。更新现场信息前先核对当前部署，不要把本文中的通用默认值当作现场实况。

## 目标和当前状态

用户可以先布置任务，再让 Agent 创建 A5 预约，或选择本人已有预约并绑定当前会话。布置任务时就询问分配卡被他人占用或无法核实时的处理，以及到期任务未完成时是否续期和如何处理；用户已经明确的选择不重复询问，并保存到执行计划。普通预约进入 `ready` 后，Agent 核对最新分配编号并登记开始；夜间预约按队列规则进入 `active` 后再启动任务。任务运行在用户指定的已有容器，Agent 按预先授权的设置处理续期、停止和释放。

已实现创建、查询和操作预约的接口；服务端保存到号、开始、到期和结束事件；本地接收器通过持续连接获取事件，并将消息交给当前 Codex 桌面会话。事件流与会话推送已用隔离队列、模拟任务验证，空闲的原 Codex 会话也已用模拟事件成功唤醒。**真实业务任务从预约、启动、续期到释放的全链路尚未完成验证；Claude 和其他运行环境的原会话适配器尚未实现或实测。**

任务的业务启动、进度判断和停止由 Agent 按用户计划负责，预约系统本身不执行提交的业务命令。当前没有通用的“业务进程完成”主动事件：任务提前完成时，能否及时释放取决于 Agent 能否观察到完成状态或后续收到其他事件。不可将登记结束当作业务进程已停止，也不可把推送被接收当作任务已经启动或完成。

## 状态与事件

- 新建预约和 `claim`、`extend`、`finish` 使用唯一操作编号；相同编号的重复请求由服务端事务回执去重。客户端结果不明时用原编号 `retry` 或 `action-retry`，不要构造新操作。
- `agent_queue_events` 记录 `ready`、`active`、`due`、`ended`，按工号关联的账号和共同使用人过滤。`ready`、`active` 由数据库状态变更写入；`due` 按每次开始时间和申请时长去重，预约删除时也会补记到期事件；`ended` 在预约记录删除时产生。不要把事件当作当前状态，处理前重新查询。
- `agent-stream` 使用已登录个人会话接收事件流；服务端检查持久事件并向连接中的接收器推送。接收器保存确认过的游标，重连时可补读。客户端不需要定期唤醒 Agent 查询预约。
- Codex 桌面适配器通过当前桌面应用提供的工具向继承的当前会话发送消息，不得将未授权的其他会话当作目标。事件编号已确认时去重；发送结果不确定时保留待核查状态，不盲目重发。接收确认不代表 Agent 已处理。
- `a5_push.py --codex-desktop --plan <绝对路径> --job <预约编号> --background` 继承当前会话身份，检查预约归属及桌面工具，启动后台接收并返回连接状态。计划应保存在用户私有目录，包含任务启动、识别、停止、输出和完成后处理方式。绑定时已到号或已在使用，应立即查询并按计划处理，不依赖新事件。
- 桌面适配器依赖 Codex 应用提供的本地插件及进程环境；升级或重启后可能需要在原会话重新绑定。电脑、接收程序或网络离线时无法保证及时操作，恢复后必须先检查预约和实际任务。

## 不可省略的业务边界

普通预约仅在服务端允许的超时窗口内申请 10、20 或 30 分钟延长，且可能受夜间截止或插空边界限制；夜间预约不能使用该普通续期接口。用户允许且选择由 Agent 估计时，Agent 根据任务进度选择档位。续期被拒绝或无法继续时按任务布置时确认的方案处理并通知；用户选择停止时，只停止对应任务并尽量保留已有输出，不能停止无关任务或整个容器。

2026-11-14 起，A5 现场启用 `midnight_separation`：普通预约跨午夜截短至 00:00 并结束登记，00:00–09:00 暂停开始普通预约，等待队列保留；夜间预约可提前提交，开始时间为 00:00–09:00 前，统一于当天 09:00 结束登记，固定卡位不再因普通任务优先而顺延。配置中的旧 `normal_priority` 值被该模式覆盖，实际状态以接口为准。结束登记不停止实际进程；夜间接管仍须依赖新鲜采集和既有非预约容器处理，信息不完整时可能暂不能开始。现场两条既有夜间预约按用户要求调整为 11 月 15 日 00:00–09:00，保留卡位。

先确认实际业务已停止使用分配卡，再按用户选择结束登记或等待；单次“无进程”采样和结束登记都不等于业务已经安全退出。现场可能启用无工号进程拦截和人员名单管控，实际启动前须核对任务归属与运行环境。当前预约接口按用户要求使用自报工号和姓名，不能把它描述为独立的企业身份认证，也不授予管理权限。

隔离数据库和假任务优先，禁止为了验证创建或停止他人真实预约和进程。以下测试需要 Python、`aiohttp` 和可用的时区数据，命令在仓库根目录执行：

```text

python -m unittest discover -s skills/ascend-resource-monitor/scripts/tests -p test_codex_desktop_adapter.py -v
```

适配器测试覆盖绑定会话、去重和未知结果不重发；HTTP 测试使用隔离队列覆盖事件推送、重连、后台接收和结束退出。原 Codex 会话的模拟推送已验证，但不能以此声称真实业务执行或 Claude 会话已验证。

后续优先工作：在用户明确指定的任务、容器和预约上验证启动到释放全链路；实现或验证任务完成时及时通知 Agent 的方案；为 Claude 等环境实现独立会话适配器；验证桌面应用重启后的恢复方式和投递不确定时的人工核查流程。任何真实任务测试都应遵循该用户的授权和预设停止、保存策略。

现场代理文件可能与通用仓库版本有差异。部署前先核对现场文件、服务配置、运行任务与变更范围，在隔离副本上测试；保留可恢复的代码和一致性数据库备份，避免直接覆盖现场特有实现。数据库备份不能随意回滚覆盖部署后产生的新预约或会话。

## Agent 预约的小鲁班提示

Agent 成功创建预约时，服务在同一事务中记录创建通知；新版接收程序成功连接并绑定已有预约时记录绑定通知。通知发送给预约人，共同使用人绑定时会显示绑定者工号，不包含会话或执行计划。通知通过现有快照和小鲁班发送链路异步处理，可能延迟，超过一小时不再发送；重试和同一接收进程重连会去重。每次重新启动接收并完成绑定会产生新的绑定通知。旧版接收程序需升级后才支持绑定通知。平台接受发送不等于用户设备收到，私聊提示不要求确认，也不改变既有到号、开始或超时提醒。
