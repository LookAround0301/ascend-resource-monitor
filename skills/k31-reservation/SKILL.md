# K3.1 版本预约 Skill

仅用于 K3.1 版本资源池：141.61.52.{179,183,187,191,220,224,228,232}。客户端会校验服务器返回的八个节点，防止误用其他资源池。机器在接口中仍叫 `A5-179` 等；不要据此改用 A5-118/124。

使用 `scripts/eight_node_client.py`，以下命令都以 `python <技能目录>/scripts/eight_node_client.py` 开头。为兼容已有客户端，保留脚本名、`EIGHT_NODE_*` 环境变量及 `~/.eight-node-reservation/` 配置、回执和事件游标目录；不覆盖 A3/A5 配置。

- 首次配置：`configure --employee 本人工号 --name 本人姓名 --url http://127.0.0.1:13179`。复用八机池监控客户端的 SSH 隧道。Agent 在中央服务器 179 本机运行时使用 `http://127.0.0.1:3000`。环境变量 `EIGHT_NODE_EMPLOYEE`、`EIGHT_NODE_NAME`、`EIGHT_NODE_QUEUE_URL` 可覆盖本机配置。非本机连接必须使用可信 HTTPS 或 SSH 隧道，不关闭证书验证。不要冒用其他人；用户身份未配置且上下文无法确定时再询问。
- 查询：`query`，只返回本人及共同使用的预约。
- 任意机器：`create --machine multi:8 --cards 8 --minutes 480`。自动机器数量 1 / 2 / 4 / 8 对应 `auto` / `dual` / `multi:4` / `multi:8`。卡数为总数，多机平均分配，每台支持 1 / 2 / 4 / 8 卡。普通任务最长 8 小时。
- 指定机器：`create --nodes 179 187 232 --cards 3 --minutes 120`。选哪些就预约哪些，允许任意非空子集；不与 `--machine` 同用。
- 避开时段：默认沿用服务端设置；`--avoid-slots` 后不带数字表示全不选，带 `24 25 26 27` 表示避开 12:00–14:00。编号 0–47 是北京时间每天的半小时时段。网页开放 09:00–24:00 的选择。仅用户同意缩短时添加 `--backfill-minutes N`。
- 时间分隔（北京时间）：普通任务最长 8 小时，只在 09:00–24:00 开始，跨午夜的时长截短至 00:00 并释放登记；00:00–09:00 新提交的普通预约排队等待。每日 09:00 清理上一普通时段的预约，保留当日 00:00 后提交的新预约。
- 夜间：增加 `--night-start "YYYY-MM-DD HH:MM"`，只可预约服务端北京时间的**明天**，开始时间 00:00–09:00 前，最长 9 小时，最晚于预约日 09:00 结束登记。先查询服务端日期和窗口；过了午夜“明天”随之改变，已有夜间预约照常保留。不要自行猜测用户要运行的日期和时长。机器、卡位和时段固定，普通任务不能占用夜间窗口；网页和 Agent 接口执行同一限制。
- 预约和结束登记本身不会启动或停止实际任务。当前 K3.1 版本资源池不自动停止进程或容器；卡位被其他任务占用、采集不新鲜或归属不明时，夜间预约等待核实，不将它视为空闲。未知进程清理和非白名单用户拦截仍关闭。
- 共同使用人由申请人管理：`shared search --job 编号 --query 姓名或工号`，`shared add --job 编号 --employee 工号`，`shared list --job 编号`，`shared remove --job 编号 --employee 工号`。添加前自动核对八机白名单上的一致姓名，多个搜索结果先确定用户指的是谁。

用户已要求预约且条件完整时直接创建。返回预约编号和实际状态。创建发送前持久保存唯一请求编号；结果未知时先 `recover 请求编号`，需要重试只用 `retry 原请求编号`，不要重复 `create`。

服务器端小鲁班负责业务提醒及 Agent 创建、绑定提示；平台接受不代表手机已经显示。通知不代替用户授权。用户要求 Agent 到号后执行、续期或管理任务时，读 [自动执行与事件推送](references/agent-loop.md)，沿用已明确的卡占用、到期和任务停止处理选择。只有验证原会话可被唤醒后才承诺无人值守执行；不要因为预约完成就启动未获授权的任务，也不要按预计时长擅自停止任务。
